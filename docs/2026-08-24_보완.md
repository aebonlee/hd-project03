## 1. 무엇이 바뀌었나

1차 개발(2026-08-21)은 기존 보고 양식을 확보하지 못해 **샘플 양식을 자체 설계**했다.
이번에 실물 양식을 받아 그 구조로 전면 교체했고, 기획자가 추가로 요청한 4가지를 넣었다.

| 요청 | 처리 |
|---|---|
| 관리자가 **전월 마감 기준 전산재고** 업데이트 | 회차 관리 탭 ① — 엑셀 업로드 |
| **등록요청 발송 + 마감일 설정** | 회차 관리 탭 ② — 마감일 저장 + 미제출 업체 일괄 발송 |
| 마감 초과 업체에 **지각일수 헤드라인** | 업체 화면 최상단 띠 |
| **전 업체 등록 완료 시 관리자 통지** | 마지막 업체 제출 시 자동 발송(회차당 1회) |
| **재고보정 O 건을 결과자료에 별도 취합** | 검토 화면에서 O/X·귀책 확정 → 총괄표 하단 「보정요청 리스트」 |

## 2. 정본 엑셀에서 읽어 낸 것

받은 파일을 시트별로 뜯어 데이터 모델을 맞췄다.

### 2.1 `전체재고` 시트 (960행) — 마스터

```
순번│업체번호│업체명│품번│품명│전산재고│실물재고│차이│aging│장기│
발생사유│처분방안│단가│재고금액│재고보정│보정금액│처리유형
```

- **`전산재고`** = 관리자가 올리는 "전월 마감 기준" 값
- **`실물재고`** = 업체가 기입하는 현재 보유 실수량
- **`재고보정`(P열)** = 요청하신 **O 표시** 컬럼. 960행 중 O가 2건
- **`보정금액`** = 차이 × 단가, **`처리유형`** = `Z05`

여기서 데이터 모델에 **`품번`(partNo)과 `업체번호`(vendorCode)를 새로 추가**했다.
1차 개발본에는 아이템 이름만 있었는데, 실제 양식은 품번으로 행을 식별한다.

### 2.2 `재고실사 총괄표` 시트 — 결과 추출물 (2단 구성)

**상단**: 업체 × [전월 마감재고 품목수·금액] [실사대상 수량·금액·실사율]
[실사결과 — 품목기준 일치/과잉/부족/일치율, 금액기준 일치/과잉/부족/NET/일치율] [비고]

**하단 「보정요청 리스트」** ← 이것이 "재고보정 O 건의 별도 취합"이다.

```
무상사급업체│품번│품명│보정수량│보정금액│귀책│조치사항│보정사유  (+업체별 소계)
```

실제 2건: 한양정밀2공장 `410102-00052E` −1개/−69,966원/귀책 **HCE**/`Z05`/자가불량(나사선 마모),
선진정공-천안 `421-00021A` −1개/−10,918원/귀책 **협력업체**/`Z05`/자가불량(파손).

### 2.3 열 의미를 추측하지 않고 실측했다

총괄표 E열은 머리글이 "품목수"인데 **라인 수가 아니라 실물재고 수량 합**이다.
`전체재고` 시트를 업체별로 합산해 대조하니 **10개 업체 전부 1원 단위까지 일치**했다.

| 업체 | 라인 수 | 실물재고 합 | 총괄표 E열 |
|---|---|---|---|
| 한국기전공업 | 174 | 4,524 | **4,524** |
| (주)태화정공 | 5 | 11 | **11** |
| 선진정공-천안 | 441 | 5,749 | **5,749** |

머리글만 보고 "품목수 = 라인 수"로 짰다면 전 업체 수치가 통째로 틀렸을 것이다.

### 2.4 보정 건이 상단 일치율에서 빠지는 구조

원본에서 **보정 2건이 있는데도 상단 일치율이 100%** 였다.
보정이 확정된 라인은 상단 집계에서 빠지고 하단 보정요청 리스트로 이관된다.
`buildSummaryRow(lines, { excludeCorrected: true })` 로 같은 동작을 재현했다.

## 3. 설계 결정

| 결정 | 이유 |
|---|---|
| **지각일수는 시각이 아니라 날짜 차이로 센다** | 마감 다음 날 0시 1분이든 23시 59분이든 똑같이 "1일 지각"이어야 화면 문구가 상식과 맞는다 |
| 지각 7일 이상이면 **노란 띠 → 빨간 띠**로 한 단계 올림 | 요청이 "빨간 헤드라인 혹은 노란 헤드라인에 빨간 글씨"였다. 기본은 노랑+빨강, 오래 방치되면 빨강 바탕 |
| 이미 제출한 업체도 **지각 제출 사실을 남긴다** | 다음 회차 독려의 근거가 된다. 냈다고 지워 버리면 기록이 사라진다 |
| **전산재고 갱신은 미제출 업체에만** 적용 | 이미 제출한 업체의 장부수량을 바꾸면 그 업체가 낸 실사 결과의 근거가 사라진다. 건너뛴 건수를 화면에 알린다 |
| 전원 완료 통지는 **회차당 1회** | 이후 승인·수정 때마다 다시 나가면 알림이 무의미해진다 (`completedNotifiedAt` 로 잠금) |
| 재고보정은 **업체가 아니라 담당자가 확정** | 귀책(HCE/협력업체) 판단이 들어가는 값이라 업체가 정할 수 없다 |
| 전산재고 엑셀은 **열 이름으로 찾는다** | 열 순서를 박아 두면 서식이 조금만 달라도 엉뚱한 값을 읽는다 |
| `localStorage` 키를 **v1 → v2** 로 올림 | 스키마가 바뀌었다. v1 그대로 두면 옛 브라우저에 남은 데이터에 회차계획·재고보정 필드가 없어 화면이 조용히 비어 보인다 |
