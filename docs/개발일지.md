- 기획: 공지은 (생성형 AI 업무자동화 전문가과정 1차수)

## 1. 요구사항 분석

기획서의 핵심 흐름은 다음과 같다.

```
업체 실무자: 사업자번호 로그인 → 대여 아이템 실사 수량 입력 → 불일치 시 소명 필수
           → 삭제(대여 종료) 요청 → 실사결과 확인서 업로드 → 제출
HD 담당자: 제출 알림 수신 → 검토(장부 vs 실사, 소명, 첨부) → 삭제 요청 승인/반려
           → [리포트 요청] → 기존 보고 양식대로 보고서 자동 생성 (수량·금액 일치도 중심)
```

- 보안 중요도 낮음 → 사업자번호 + 비밀번호 수준 인증. 단 **업체 간 데이터 교차 노출 금지**는 필수.
- 기존 보고 양식 파일은 미확보 → 표지 요약 + 업체별 시트 구조의 샘플 양식을 자체 설계 (양식 확보 시 교체 가능).

## 2. 설계 결정

| 결정 | 이유 |
|---|---|
| 단일 페이지 웹앱 + localStorage 데모 DB | 개인 환경에서 서버 없이 전체 흐름 검증. GitHub Pages 배포 가능 |
| 역할 분리(업체 실무자 / HD 담당자)를 로그인 화면에서 전환 | 기획서의 두 사용자 유형을 한 앱에서 데모 |
| 비즈니스 로직을 `js/logic.js`(UMD)로 분리 | 권한 필터·제출 검증·일치도 계산을 Node에서 단위 테스트 |
| 알림은 알림 로그 + 어댑터 | 메일/문자 수단 무관이라는 기획 조건. 실연동(Resend/SMTP)은 README 안내 |
| Supabase 스키마(`supabase/schema.sql`) 동봉 | 실서비스 전환 시 Postgres + RLS(업체 격리) + 제출 검증 트리거로 즉시 이관 가능 |

## 3. 구현 내역

1. **업체 실무자 화면**: 사업자번호+비밀번호 로그인(데모 계정 표), 본인 업체 아이템만 표시(권한 필터로 격리), 실사 수량 입력 → 일치/불일치 자동 판정, 불일치 소명 미입력 시 제출 차단, 삭제(대여 종료) 요청, 확인서 업로드(10MB, PDF/JPG/PNG, 이미지 미리보기), 제출 → 담당자 알림.
2. **HD 담당자 화면**: 업체별 제출 현황 대시보드(미제출/제출/불일치 있음/승인 완료), 제출 상세 검토, 삭제 요청 승인/반려, 실사 승인, 제출 독려 알림, 알림 로그, 기준 데이터(업체/아이템) 엑셀 임포트·내보내기.
3. **보고서**: SheetJS 엑셀 생성 — 표지 요약(전체 수량 일치도 %, 금액 일치도 %, 불일치 건수, 삭제 요청 내역) + 업체별 시트. 인쇄용 PDF 뷰(window.print) 병행.
4. **시드 데이터**: 업체 5곳, 업체당 아이템 10~14개, 불일치 3건·삭제요청 1건·승인 완료 1개사 포함. "데모 데이터 초기화" 버튼 제공.

## 4. 테스트 및 검증

- `node test/logic.test.js` — **34개 테스트 통과** (인증, 업체 간 권한 격리, 실사 라인 계산, 제출 검증 3종, 파일 검증, 수량·금액 일치도 계산식, 현황 분류, 대시보드 집계)
- Node 스모크 테스트(mocked window/localStorage): 시드 무결성, 저장/재로드 왕복, 대시보드 집계 {전체 5, 미제출 2, 제출 1, 불일치 1, 승인 1}, 보고서 집계(수량 일치도 97.1%, 금액 98.6%) 확인
- 전체 JS `node --check` 통과

## 5. 트러블슈팅

| 이슈 | 해결 |
|---|---|
| 금액 일치도가 항상 100%로 계산되는 버그 | 실사 라인 계산 시 `unitPrice`/`bookAmount` 누락이 원인 — 단위 테스트 과정에서 발견, 계산 필드 보강으로 해결 |
| 업체 간 데이터 노출 위험 | 모든 조회를 `filterByVendor` 권한 필터 경유로 강제, 테스트로 격리 검증. Supabase 전환 시 RLS 정책으로 동일 규칙 적용 |
