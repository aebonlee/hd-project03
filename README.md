# 업체 대여 아이템 재고관리 보고서 자동화

> 기획: 공지은 · 생성형 AI 업무자동화 전문가과정 [1차수] 프로젝트

여러 협력업체가 HD로부터 대여해 간 아이템(자산)의 **재고 실사 결과를 업체가 직접 웹에서 입력하고 확인서를 업로드**하면, HD 담당자에게 알림이 가고, 담당자가 검토·승인 후 **수량·금액 일치도 중심의 보고서를 자동 생성**하는 웹 포털입니다.

- 빌드 없이 동작하는 순수 HTML/CSS/JS 단일 페이지 앱 (GitHub Pages 배포 가능)
- 데모 DB: 브라우저 `localStorage` (최초 실행 시 샘플 데이터 자동 생성)
- 엑셀 보고서/임포트: [SheetJS](https://sheetjs.com/) (CDN)
- 운영 전환용 Postgres 스키마 + RLS 정책: [`supabase/schema.sql`](supabase/schema.sql)

## 데모 사용법 (역할별 시나리오)

`index.html`을 브라우저로 열면 됩니다. 최초 실행 시 샘플 데이터(업체 5곳, 업체당 아이템 10~20개, 불일치·삭제요청 사례 포함)가 자동 생성됩니다. 언제든 로그인 화면 또는 담당자 화면의 **[데모 데이터 초기화]** 버튼으로 처음 상태로 되돌릴 수 있습니다.

### 시나리오 A — 업체 실무자: 실사 입력부터 제출까지

1. 로그인 화면에서 **업체 실무자** 탭 선택 → 데모 계정 표에서 **대한테크**의 [자동 입력] 클릭 → 로그인. (대한테크는 미제출 상태라 전체 흐름을 처음부터 체험할 수 있습니다.)
2. 본인 업체가 대여 중인 아이템 목록(아이템명, 규격, 대여수량, 단가, 금액, 대여일)이 표시됩니다. **다른 업체의 데이터는 절대 보이지 않습니다.**
3. 각 아이템의 **실사 수량**을 입력하면 장부 수량과 비교해 **일치/불일치가 자동 판정**되고, 상단 카드에 수량·금액 일치도가 실시간 계산됩니다.
4. 장부와 다른 수량을 입력해 보세요 → 해당 행의 **소명 사유** 입력칸이 활성화됩니다. 소명 없이 제출하면 제출이 차단됩니다.
5. 현재 존재하지 않는 아이템은 **[삭제 요청]** 체크 → 사유 입력 (담당자 승인 대기 상태가 됩니다).
6. **실사결과 확인서**(PDF/JPG/PNG, 최대 10MB)를 첨부합니다. 첨부가 없으면 제출이 차단됩니다.
7. **[실사 결과 제출]** 클릭 → 제출 완료. HD 담당자에게 알림(알림 로그)이 발송되고, 이후 화면은 읽기 전용이 됩니다.

### 시나리오 B — HD 담당자: 검토·승인·보고서

1. 로그아웃 후 **HD 담당자** 탭 → 비밀번호 `hd1234` 로 로그인.
2. **제출 현황** 대시보드: 업체별 미제출 / 제출 / 불일치 있음 / 승인 완료 현황과 일치도 요약이 표시됩니다.
3. **서울정공** 행을 클릭 → 제출 상세 검토: 장부 vs 실사 수량, 금액 차이, 소명 내용, 첨부 확인서를 확인합니다.
4. 서울정공의 **삭제 요청**("보루 압축팩")을 **[승인]** 또는 **[반려]** 처리합니다. (승인 시 해당 아이템은 "종료" 상태가 되고 업체에 알림이 발송됩니다.)
5. 삭제 요청 처리 후 **[실사 승인]** → 해당 업체는 "승인 완료"로 바뀝니다.
6. 미제출 업체(예: 청우전자)를 클릭하면 **[제출 독려 알림 보내기]** 를 사용할 수 있습니다.
7. **알림 로그** 탭에서 발송된 알림 이력을 확인합니다.
8. **[리포트 요청 (인쇄 보기)]** → 표지 요약 + 업체별 상세가 담긴 보고서 화면이 열립니다. **[PDF로 인쇄]** 는 브라우저 인쇄(`window.print`)로 PDF 저장, **[엑셀 다운로드]** 는 SheetJS로 `재고실사보고서_2026-08.xlsx` 를 생성합니다.

### 시나리오 C — 기준 데이터 관리

1. HD 담당자 로그인 → **기준 데이터 관리** 탭.
2. **[현재 데이터 엑셀 내보내기]** → "업체" / "아이템" 두 시트가 담긴 엑셀 파일 다운로드.
3. 내보낸 파일을 수정(업체 추가, 아이템 수량·단가 변경 등)한 뒤 **[엑셀 업로드(임포트)]** 로 다시 올리면 기준 데이터가 교체됩니다. 임포트 양식은 내보내기 파일과 동일합니다.

## 데이터 모델

`localStorage` 키 `hd_rental_audit_db_v1` 아래 하나의 JSON 문서로 저장됩니다. (운영 스키마는 [`supabase/schema.sql`](supabase/schema.sql) 참조 — 테이블/컬럼이 1:1로 대응합니다.)

| 엔터티 | 주요 필드 | 설명 |
|---|---|---|
| **Vendor** (업체) | `bizNo`(사업자번호=로그인 ID), `name`, `manager`, `phone`, `email`, `password` | 협력업체 |
| **RentalItem** (대여 아이템) | `id`, `bizNo`, `name`, `spec`, `qty`(장부수량), `unitPrice`, `amount`, `rentedAt`, `status`(대여중/종료요청/종료) | 업체가 대여 중인 자산 |
| **Audit** (실사) | `id`, `bizNo`, `round`(예: 2026-08), `submittedAt`, `status`(작성중/제출/검토중/승인) | 회차별 업체 제출 단위 |
| **AuditLine** (실사 상세) | `auditId`, `itemId`, `bookQty`, `actualQty`, `diff`, `amountDiff`, `reason`(소명), `deleteRequested`, `deleteStatus`(대기/승인/반려) | 아이템별 실사 결과 |
| **Attachment** (첨부) | `auditId`, `fileName`, `size`, `type`, `preview` | 실사결과 확인서 (데모는 파일명 + 이미지 미리보기만 저장) |
| **Notification** (알림 로그) | `id`, `to`, `channel`, `message`, `sentAt` | 이메일 발송 이력 (데모는 로그로 대체) |

## 보고서 지표 정의

보고서(엑셀 요약 시트·인쇄 뷰·대시보드)는 아래 계산식을 사용합니다. 구현: [`js/logic.js`](js/logic.js) `computeMatchRates()`.

| 지표 | 계산식 |
|---|---|
| **수량 일치도(%)** | `(1 − Σ\|실사수량 − 장부수량\| ÷ Σ장부수량) × 100` |
| **금액 일치도(%)** | `(1 − Σ\|금액차이\| ÷ Σ장부금액) × 100` (금액차이 = 수량차이 × 단가) |
| **라인 일치율(%)** | `일치 라인 수 ÷ 실사 입력 라인 수 × 100` |
| **불일치 건수** | `diff ≠ 0` 인 라인 수 (삭제 요청 라인 포함) |
| **삭제 요청 내역** | `deleteRequested = true` 라인의 아이템/수량/사유/처리 상태 |

계산 규칙:

- **삭제(대여 종료) 요청 라인은 실사수량 0으로 간주**되어 차이에 포함됩니다.
- 실사수량이 입력되지 않은 라인은 지표 계산에서 제외됩니다.
- 장부 수량(또는 금액) 합계가 0이면 0 나누기를 피하기 위해 100%로 처리합니다.
- 일치도는 소수 첫째 자리에서 반올림하며 음수가 되면 0%로 표시합니다.
- 전체 일치도는 제출된 모든 업체의 라인을 합산해 같은 식으로 계산합니다(업체별 평균이 아님).

## 알림(이메일) 실제 연동 방법

데모에서는 이메일 발송을 **알림 로그**(`Store.notify()`)로 대체합니다. 실제 연동 시 이 어댑터 한 곳만 교체하면 됩니다.

1. **Supabase Edge Function + Resend(권장)**
   - Resend에서 API 키 발급 → Supabase 프로젝트 시크릿에 `RESEND_API_KEY` 저장.
   - Edge Function `send-notification` 을 만들어 `POST https://api.resend.com/emails` 호출 후 `notification` 테이블에 이력 insert.
   - 프런트의 `Store.notify(to, message)` 내부를 `supabase.functions.invoke('send-notification', { body: { to, message } })` 호출로 교체.
2. **SMTP(사내 메일 서버)**: 같은 Edge Function에서 `nodemailer` 대신 Deno SMTP 클라이언트를 사용하거나, 사내 게이트웨이 API를 호출.
3. **문자(SMS) 추가**: `channel` 필드가 이미 있으므로 같은 함수에 알리고/NHN Cloud SMS 등 어댑터를 추가하고 `channel: '문자'` 로 기록.

## Supabase 전환 가이드

localStorage 데모를 실제 다중 사용자 서비스로 전환하는 순서입니다.

1. **프로젝트 생성**: [supabase.com](https://supabase.com)에서 새 프로젝트 생성.
2. **스키마 적용**: SQL Editor에서 [`supabase/schema.sql`](supabase/schema.sql) 전체 실행 — 테이블 6종(vendor, rental_item, audit, audit_line, attachment, notification) + `hd_manager`, RLS 정책, 제출 검증 트리거, 보고서 뷰(`report_vendor_summary`)가 생성됩니다.
3. **업체 계정 발급**: 업체마다 Supabase Auth 사용자를 생성합니다. 이메일 대신 사업자번호 기반 가상 이메일(`{사업자번호}@vendor.hd.example.com`)과 초기 비밀번호를 부여하고, 생성된 `auth.users.id` 를 `vendor.auth_user_id` 에 연결합니다. HD 담당자는 `hd_manager` 테이블에 등록합니다.
4. **데이터 이관**: 담당자 화면의 [현재 데이터 엑셀 내보내기]로 받은 파일을 Supabase Table Editor의 CSV 임포트로 올리거나, `schema.sql` 하단의 시드 INSERT를 참고해 적재합니다.
5. **스토리지**: `audit-certificates` 버킷 생성(비공개). 업로드 경로를 `{biz_no}/{round}/파일명` 으로 통일하고, 경로의 `biz_no` 가 `current_biz_no()` 와 일치할 때만 읽기/쓰기 되도록 Storage 정책을 추가합니다. 10MB·MIME 제한은 버킷 설정으로 강제합니다.
6. **프런트 교체**: `js/store.js` 가 데이터 접근의 단일 창구이므로, 이 파일의 `load/save/notify` 를 `@supabase/supabase-js` 호출로 교체합니다.
   - 조회: `supabase.from('rental_item').select()` — RLS 덕분에 프런트에서 `filterByVendor` 를 호출하지 않아도 본인 데이터만 반환됩니다(로직 필터는 이중 안전장치로 유지 권장).
   - 제출: `supabase.from('audit').update({ status: '제출' })` — 소명 누락·첨부 누락은 DB 트리거(`check_submission`)가 한 번 더 차단합니다.
   - `js/logic.js` 의 계산·검증 로직과 `js/report.js` 의 보고서 생성은 그대로 재사용됩니다.
7. **알림**: 위 [알림 연동](#알림이메일-실제-연동-방법) 절차대로 Edge Function 연결.

## GitHub Pages 배포법

빌드 단계가 없으므로 저장소 루트를 그대로 배포하면 됩니다.

1. GitHub 저장소 → **Settings → Pages**.
2. Source: **Deploy from a branch** 선택.
3. Branch: `main` / 폴더 `/ (root)` 선택 후 저장.
4. 1~2분 후 `https://<계정명>.github.io/hd-project03/` 에서 접속 가능합니다.

> 데모 데이터는 방문자 각자의 브라우저 localStorage에 저장되므로 별도 서버 없이 시연할 수 있습니다.

## 개발 / 테스트

```
index.html          # 단일 페이지 앱 (역할별 화면 전환)
css/style.css       # 라이트 코퍼레이트 스타일
js/logic.js         # 순수 비즈니스 로직 (일치도 계산·제출 검증·권한 필터) — Node 테스트 대상
js/store.js         # localStorage 데모 DB + 시드 데이터
js/report.js        # SheetJS 엑셀 보고서 / 기준 데이터 임포트·내보내기
js/app.js           # 화면 컨트롤러
test/logic.test.js  # 단위 테스트
supabase/schema.sql # 운영용 Postgres 스키마 + RLS 정책
```

단위 테스트 실행 (Node.js만 있으면 됩니다):

```bash
node test/logic.test.js
```

인증·권한 필터·실사 라인 계산·제출 검증(소명 필수/첨부 필수)·첨부 파일 검증·일치도 계산식·제출 현황 분류·대시보드 집계를 검증하는 34개 테스트가 실행됩니다.
